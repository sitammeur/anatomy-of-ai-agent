Section 01  ·  Model

The model is not the agent

  • —Takes text in, produces text out. Nothing more.
  • —No memory between calls, no loop that keeps it running.
  • —Can express the intent to call a tool, but can't act on it.
model_call.py
response = client.chat.completions.create(
    model=MODEL,
    messages=[{"role": "user", "content": "What's 17 * 24?"}],
)
print(response.choices[0].message.content)

# A fresh call with no history gets nothing back.
# Memory is something WE build, not something
# the model has natively.
tools_schema.py
tools_schema = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "Get the current weather for a city.",
        "parameters": {
            "type": "object",
            "properties": {"city": {"type": "string"}},
            "required": ["city"],
        },
    },
}]
Section 02  ·  Scaffolding

Scaffolding is data, not a loop

  • —The system prompt, tool schemas, and message list.
  • —Shapes how the model sees the world and can act in it.
  • —If a tool's description is bad, the model will misuse it.
Section 03  ·  Harness

The harness is what makes it run

  • —Calls the model, notices tool calls, executes real code.
  • —Feeds results back into context, calls the model again.
  • —Decides when the task is actually done. That's the loop.
harness.py
for turn in range(max_turns):
    response = client.chat.completions.create(...)
    msg = response.choices[0].message

    if not msg.tool_calls:
        return msg.content

    for tc in msg.tool_calls:
        result = AVAILABLE_TOOLS[tc.function.name](**args)
        messages.append({"role": "tool", "content": str(result)})
Section 04  ·  Agent

Agent = Model + Harness

Pack a model and a harness into one class, working from the scaffolding you already built, and you have an agent.
memory.py
def save_memory(fact: str):
    facts = load_memory()
    facts.append(fact)
    json.dump(facts, open(MEMORY_FILE, "w"))

prompt = SYSTEM_PROMPT + "\n\nWhat you know:\n" + (
    "\n".join(f"- {f}" for f in load_memory())
)
Section 05  ·  Context Engineering

Deciding what enters the window

  • —Short-term memory: messages growing within one run.
  • —Long-term memory: stored externally, retrieved on demand.
  • —A fresh agent has zero memory until you inject it back in.
Section 06  ·  Policy

Same weights, different behavior

  • —Policy is the weights, plus the scaffolding and harness wrapped around them.
  • —Swapping only the system prompt changes behavior completely.
  • —Even "thinking mode" is a scaffolding switch, not a weights change.
policy.py
terse_agent = Agent(MODEL,
    "Answer in 5 words or fewer. No explanations.",
    tools_schema, AVAILABLE_TOOLS)

think_agent = Agent(MODEL,
    "<|think|>\n" + SYSTEM_PROMPT,
    tools_schema, AVAILABLE_TOOLS)

# Same model underneath both. Only the prompt differs.
Section 07  ·  Tool Use

When tool calls fail

  • —Bad arguments, wrong types, tools that don't exist.
  • —The harness can feed the error back as a tool result.
  • —The model sees its own mistake and tries again, instead of crashing.
error_handling.py
try:
    fn_args = json.loads(tool_call.function.arguments)
    result = available_tools[fn_name](**fn_args)
except Exception as e:
    result = f"Error: {e}"

messages.append({"role": "tool", "content": str(result)})
Section 08  ·  Skills

Instructions, loaded only when needed

—A skill is plain instructions. A tool is code that runs.
—Stays out of the prompt until the user's message triggers it.
—Keeps the base prompt lean instead of front-loading everything.
skills.py
SKILLS = {"trip_itinerary": {
    "trigger_words": ["itinerary", "day trip"],
    "instructions": "Format as 'Day N: <plan>'.",
}}

def build_system_prompt(base, user_input, skills):
    for skill in skills.values():
        if any(w in user_input for w in skill["trigger_words"]):
            base += skill["instructions"]
    return base
subagent.py
packing_subagent = Agent(MODEL,
    "Given a weather description, give ONE packing tip.",
    tools_schema=[], available_tools={})

def delegate_to_packing_subagent(weather_description):
    return packing_subagent.run(weather_description)

# The orchestrator calls this exactly like any other tool.
Section 09  ·  Sub-agents

A tool that thinks for itself

  • —A full independent Agent, with its own messages, prompt, and harness loop.
  • —Exposed to the orchestrator as if it were a plain tool.
  • —The orchestrator only ever sees its final answer, not its reasoning.
Section 10  ·  Multimodal Input

Same model, richer input

  • —Gemma 4 accepts an image in the same message list as text.
  • —Still one call to the same model, just with content as a list of parts.
  • —A real photo in, a real description out, feeding the next agent.
